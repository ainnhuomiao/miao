# 从哪里开始读代码

先记住一条执行路线：

```text
main → run → Agent.Send → HTTPClient.Chat → readStream
                   ↑                            │
                   └── 保存完整回答 ← 返回结果 ──┘
                           文字回调 → 终端
```

不必一次掌握全部语法。先读入口和交互循环，再读历史，最后读网络。

## 第一步：读 cmd/miao/main.go

先找到 `func main()`。这是程序入口：读取三个环境变量，创建网络客户端，调用 `run`。

`:=` 是声明变量并赋初值，Go 会推断类型。`client, err := ...` 同时接收两个返回值：一个结果和一个错误。

看到 `if err != nil`，可以读作“刚才那件事失败了吗？”。Go 通常用返回错误表达失败，没有在这里使用异常捕获。

然后读 `run`。它用 `for` 重复做四件事：显示提示、读一行、识别命令、请求回答。`switch` 根据输入选择分支；`continue` 开始下一轮，`return` 离开函数。

`io.Reader` 表示能读取字节的对象，`io.Writer` 表示能写入字节的对象。终端、文件、字符串和内存缓冲区都可能实现这些接口，所以测试不需要真人敲键盘。

文件末尾的 `func(part string) error { ... }` 是匿名函数，被作为参数传给 `Send`。这是**回调**：稍后收到文字时才调用它。它使用了外层的 `output`，因此也是**闭包**。

`context.Background()` 创建没有截止时间的根 context。网络层另有 60 秒超时；本版 Ctrl+C 由终端直接结束程序。不要把 context 理解成保存聊天内容的地方。

## 第二步：读 internal/agent/agent.go

`struct` 把相关字段放在一起。`Agent` 里只有客户端和历史；没有隐藏的全局会话。

`*Agent` 是指针，`&Agent{...}` 取得新对象的地址。方法接收者 `(a *Agent)` 让方法能修改同一个 Agent 的历史。

`[]llm.Message` 是消息切片。切片可以增长；`append` 的返回值必须接住，因为底层存储可能变化。

重点读 `Send`：先复制历史，再加用户输入，请求模型，最后一起保存用户输入和回答。请求失败时直接返回，原历史不变。因为本版没有文件写入等外部副作用，这个规则可以保持很简单。

`Reset` 用一份只含系统消息的新切片替换历史，旧问答就不会出现在下一次请求里。

可以手工画出两次 `Send` 前后的切片，确认每个元素的角色和顺序。

## 第三步：读 internal/llm/client.go

先看 `Message`。反引号中的 `json:"role"` 是结构体标签，告诉标准库 JSON 字段应叫什么。

再看 `Client` 接口：任何拥有相同 `Chat` 方法的类型都能使用，不必继承某个类。这里需要接口，是为了让对话层能使用真实客户端，也能在测试里使用假客户端。

`HTTPClient` 是具体实现，保存请求地址、密钥、模型和可复用的 HTTP 客户端。`New` 检查参数，`Chat` 负责一次网络请求。

HTTP 请求由地址、方法、请求头和请求体组成：

- 方法是 POST。
- `Authorization` 请求头携带密钥。
- 请求体是 `json.Marshal` 生成的 JSON 字节。
- `stream: true` 请求服务端逐段发送回答。

`defer` 把关闭响应体的动作安排到函数结束时。`fmt.Errorf("...: %w", err)` 添加上下文，同时保留原错误，测试可以用 `errors.Is` 识别它。

最后读 `readStream`。SSE 是一种流式响应格式；程序反复读行，只解析 `data:` 的内容。JSON 中的 `delta.content` 是本次新增文字，不是完整回答。

每一段文字有两个去向：`strings.Builder` 拼接完整回答；`onText` 回调立即显示它。只有正常结束原因和 `[DONE]` 都出现，完整回答才返回给 Agent 保存。

## 第四步：读测试

顺序是 `internal/agent/agent_test.go` → `cmd/miao/main_test.go` → `internal/llm/client_test.go`。

`*_test.go` 文件只在测试时参与构建。`func TestXxx(t *testing.T)` 是 Go 自动寻找的测试入口；`t.Fatal` 表示当前测试失败。

测试中的假客户端返回预先约定的回答。网络测试用内存里的 HTTP 响应，仍检查地址、请求头、JSON 和流式解析，但不连接模型服务，也不花 API 额度。

表驱动测试把多个输入放进表里，复用同一套判断。先理解一个正常例子，再看断流、截断、取消和空回答。

## 第一个练习

先自己给 `/help` 加一句说明，运行程序确认。再尝试添加 `/count`：显示当前完整问答有几轮。动手前先回答“谁拥有历史”和“系统消息算不算一轮”，再决定在哪个包增加方法和测试。
