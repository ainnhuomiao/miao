# 学习路线：一次增加一个概念

每个阶段都以“自己能解释 + 程序能运行 + 行为有测试”为完成条件。当前只实现阶段 1，后续阶段没有预先留框架。

## 阶段 0：Go 的基本语法

结合代码导读认识变量、函数、多返回值、if、for、switch、结构体、指针、切片和错误。

验收：能从 main 追踪一句输入，自己修改帮助文字并运行。

## 阶段 1：终端多轮对话（当前代码）

理解环境变量、JSON、HTTP、SSE、接口、回调，以及显式保存的对话历史。

验收：能解释为什么每次请求都要带历史，为什么失败回答不记录。独立实现 `/count` 并测试。

## 阶段 2：先认识工具调用的数据

先用一个没有外部副作用的工具，例如查询固定课程表。认识 tool_calls、工具名、JSON 参数和 tool_call_id。

验收：用假客户端展示“模型请求工具 → Go 函数返回结果”，暂不操作文件或执行命令。

## 阶段 3：让工具结果回到模型

增加一个串行循环，让模型根据工具结果继续回答。设置明确的循环次数上限，不加并发。

验收：画出 user、assistant/tool_calls、tool、assistant 的消息顺序，测试错误工具名和循环超限。

## 阶段 4：只读文件工具

学习路径边界、os.Root、普通文件与符号链接，限制读取大小，禁止读取密钥和敏感目录。

验收：读取普通文件成功；越界、敏感路径、符号链接绕过和设备文件被拒绝。增加能力前人工审核边界。

## 阶段 5：需要确认的文件写入

先展示目标和内容，由用户明确确认。学习原子写入和部分完成：写入已发生后，不能因为后续网络失败就抹去执行记录。

验收：拒绝后文件不变；写入失败可见；写入成功后网络失败仍保留操作事实。

## 阶段 6：按需要选学

先学 context 取消，再考虑会话落盘。并发、TUI、子代理和 MCP 分别作为独立课题，遇到真实学习需求再选，不同时加入。

每一步只做一个小提交，写清问题、目标、范围、接口、状态、不变量、约束、测试和回滚。密钥存储、文件/命令权限和持久化格式必须由人审核。
