# miao · 从零学习 Go 和 Agent

这是一个只有 **3 个生产 Go 文件、0 个第三方依赖**的终端对话程序。
代码有中文注释。建议从 [代码导读](docs/READING_GUIDE.md) 开始，配合 [零基础学习资料](docs/RESOURCES.md)，再按 [学习路线](docs/ROADMAP.md) 逐步扩展。

## 1. 问题：这一版解决什么

把“输入一句话 → 请求模型 → 显示回答 → 继续聊天”做完整，用它学习 Go 的函数、结构体、切片、接口、错误处理和 HTTP。

当前是 Agent 的对话基础，还没有“模型选择工具 → 程序执行工具 → 结果交回模型”的工具循环。

## 2. 目标：什么算学会

你能独立解释以下问题，并通过测试验证自己的修改：

- 程序从哪里启动？一句输入经过哪些函数？
- 模型为什么能回答“我刚才说了什么”？
- 回答为什么可以边生成边显示？
- 网络断开后，为什么下一次请求不包含失败的那一轮？
- `/clear` 改变了哪一份数据？

程序能运行，但你无法解释这些过程，仍不算完成这一阶段。

## 3. 范围：第一版的边界

保留：逐行终端输入、流式文字输出、内存中的多轮历史、`/help`、`/clear`、`/exit`。

暂不实现：文件工具、命令执行、TUI、会话落盘、图片、多协议、子代理、MCP、hooks、自动重试、上下文压缩和配置管理。

这是一次学习用途的源码重置。旧版命令和配置不再生效；程序不读取 `.env`、`~/.miao` 或项目配置，不迁移或删除它们。

### 运行

需要 Go 1.26.9 或更新版本。Nix 用户可以先运行 `nix develop`。

```bash
# Bash 中隐藏输入密钥，避免把真实密钥写进一条 shell 命令。
read -rsp 'API Key: ' MIAO_API_KEY
export MIAO_API_KEY
printf '\n'
make run
```

默认使用已有的 DeepSeek 地址及 `deepseek-chat`。其他 Chat Completions 兼容服务需要自行设置地址和模型：

```bash
export MIAO_BASE_URL='https://api.example.com/v1'
export MIAO_MODEL='服务商提供的普通对话模型名'
make run
```

地址必须包含服务商要求的路径前缀，例如 `/v1`；程序会追加 `/chat/completions`。

```text
你 > 我叫小明
miao > 你好，小明！
你 > 我叫什么？
miao > 你叫小明。
你 > /clear
对话已清空。
你 > /exit
```

Ctrl+C 退出整个程序；没有单独的“只取消当前回答”操作。关闭程序后历史消失。

## 4. 架构：三个文件，各做一件事

```text
cmd/miao/main.go           读取环境变量、终端输入和输出
        ↓
internal/agent/agent.go    组织对话历史，成功后保存本轮
        ↓
internal/llm/client.go     编码 JSON、发送 HTTP、解析流式响应
```

入口创建客户端，再传给 Agent。Agent 通过 `llm.Client` 接口调用客户端；网络层不依赖终端，也不保存历史。所有对话操作按顺序执行，不引入额外 goroutine 或全局可变状态。

## 5. 接口：输入、输出、错误、副作用

| 函数 | 输入 | 输出 | 副作用 |
| --- | --- | --- | --- |
| `run` | context、客户端、输入流、输出流 | error | 读输入、写终端、驱动对话 |
| `Agent.Send` | context、用户文字、文字回调 | error | 请求模型；成功后更新历史 |
| `Client.Chat` | context、消息切片、文字回调 | 完整回答、error | 网络请求，可能产生服务费用 |
| `Reset` | 无 | 无 | 将历史替换成最初的系统说明 |

回调是一段传进去的函数。每收到一小段文字，网络层就调用它，终端立即显示。

`error == nil` 表示成功。网络、解析或回调失败时返回错误；已显示的部分回答不会保存为完整问答。

## 6. 数据：历史放在哪里

核心结构只有 `Message{Role, Content}`，以及持有客户端和 `[]Message` 的 `Agent`。

```text
system: 你是 miao……
user: 我叫小明
assistant: 你好，小明！
user: 我叫什么？
```

服务端收到的是整份消息列表。这里的“记忆”来自每次重新发送历史，不是模型在本地偷偷记住了用户。

API Key 只在 HTTP 客户端里保存，并作为请求头发送；不加入消息。没有数据库、会话文件或后台任务。

## 7. 语义：必须保持的规则

- 系统说明始终在第一条。
- 先构造候选消息，只有完整成功后才把用户消息和回答一起加入历史。
- 流式文字从 `delta.content` 取得；第一版只处理第一份回答。
- 同时收到正常结束原因 `stop` 和 `[DONE]` 才接受回答。截断、断流和空回答都报错。
- 不自动重试，避免重复输出或重复请求。
- `/clear` 只清空本程序内存中的历史，不向服务商发送删除请求。

## 8. 约束：保持简单，也说明限制

只使用 Go 标准库和一种 Chat Completions 文字流协议。支持常见的“每个 `data:` 行是一份 JSON”的 SSE 格式；尚未处理其他流协议、工具调用和专用思考模型字段。

单次 HTTP 请求最多 60 秒，单个 SSE 行最多 1MiB。历史没有自动压缩，越长就需要发送更多内容；这一阶段手动 `/clear`。

程序没有工作区读写工具、shell 或外部扩展。HTTP 不跟随重定向，服务端错误正文不直接输出，避免意外回显密钥或对话。使用普通对话服务时，消息会发送给你配置的服务商。

## 9. 过程：每次只学和改一件事

```bash
make build       # 编译到 bin/miao
make test        # 测试使用内存中的假响应，不需要密钥，也不联网
make check       # 格式、构建、vet、测试、race、lint
nix flake check  # Nix 环境下构建并测试
```

先理解现有代码，再提出一个小改动，补相应行为测试，检查 diff，最后提交。提交使用 `type(scope): summary`，例如 `feat(cli): 添加历史条数命令`。

验收：连续提问能携带历史；清空后历史消失；失败后能继续输入；不完整回答不进入历史。

旧版代码仍在 Git 历史中，重置前基线为 `db7c0a5`。可以用 `git show db7c0a5:internal/agent/agent.go` 只读查看旧实现。恢复旧版时使用独立目录或分支，先保留当前学习成果。
